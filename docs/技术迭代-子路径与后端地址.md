# 技术迭代：sub-web 子路径部署与 NPM 联调

> **本仓库职责**：Vite/Vue 构建配置、默认 subconverter 后端地址、UI placeholder 与下拉候选、容器内 Nginx（`nginx.subw.conf`）。  
> **不在此仓库**：NPM 反代 `location`、QNAP 证书（见 `nginx-proxy-manager` 仓库）。  
> **subconverter**：容器与 `/subapi` 路径见 `subconverter` 仓库文档。  
> **外网访问示例**：`https://<你的公网域名>:<HTTPS端口>/subw/`  
> **版本**：2026-05-16

## 1. 问题与目标

| 问题 | 根因 | 本仓库修复 |
|------|------|------------|
| `/subw/` 白屏 | `base: "/"`，Vue Router 在 `/subw/` 无匹配 | `VITE_BASE_PATH=/subw/` |
| Mixed Content | 构建进包的 `DEFAULT_BACKEND` 为 `http://...:25500` | HTTPS + 反代路径 `/subapi` |
| 后端示例写死在 UI | placeholder 硬编码域名 | 从 `CONSTANTS.DEFAULT_BACKEND` 动态生成 |
| 直连容器端口白屏 | HTML 引用 `/subw/assets/`，磁盘在 `/assets/` | `nginx.subw.conf` 重写 |
| 访问容器根路径 `/` 白屏 | 未跳转子路径 | `/` → `302 /subw/` |

NPM 侧曾用 `sub_filter` 过渡；**新镜像上线后**仅需 `location ^~ /subw/` 剥前缀反代，无需改 JS。

## 2. 环境变量

**勿提交 `.env`**（已 gitignore）。仓库提供两份可提交模板：

| 文件 | 场景 | 【必改】项数 |
|------|------|-------------|
| `.env.default` | 与 **master 一致**：根路径 + `api.wcc.best` | **0**（复制即可 build） |
| `.env.example` | **NAS + NPM** `/subw/` + 自建 `/subapi` | **2**（见下表） |

本地 `.env` 与所选模板**结构相同**，仅把【必改】【可改】换成真实值。

### 2.1 `.env.default`（默认部署）

| 变量 | 分类 | 说明 |
|------|------|------|
| `VITE_SUBCONVERTER_DEFAULT_BACKEND` | 沿用默认 | `https://api.wcc.best`，公共后端，无需自建 |
| `VITE_PROJECT` 等链接类 | 沿用默认 | 见文件内注释 |
| `VITE_MYURLS_API` / `VITE_CONFIG_UPLOAD_API` | 可改 | 不用对应功能可删 |
| `VITE_BASE_PATH` | — | **不设置**（根路径 `/`） |

### 2.2 `.env.example`（NPM 子路径）

| 变量 | 分类 | 填什么 |
|------|------|--------|
| `VITE_BASE_PATH` | **必改** | `/subw/`（与 NPM `location` 一致，**以 `/` 结尾**） |
| `VITE_SUBCONVERTER_DEFAULT_BACKEND` | **必改** | `https://<域名>:<端口>/subapi`（HTTPS，**勿带** `/sub?`） |
| `VITE_BACKEND_OPTION_LOCAL` | 可改 | 本机 `http://127.0.0.1:25500/sub?`；不需要可删 |
| `VITE_MYURLS_API` / `VITE_CONFIG_UPLOAD_API` | 可改 | 自建则改；不用可删 |
| `VITE_PROJECT` 等 | 沿用默认 | 与 `.env.default` 相同，一般不改 |

生成订阅时若未填「后端地址」，使用 `DEFAULT_BACKEND` = `VITE_SUBCONVERTER_DEFAULT_BACKEND` + `/sub?`。

## 3. 源码与镜像改动清单

| 文件 | 改动 |
|------|------|
| `vite.config.js` | `loadEnv` 读取 `VITE_BASE_PATH`（Docker 构建必须，否则仍为 `base: "/"`） |
| `src/router/index.js` | `import.meta.env.BASE_URL` |
| `src/config/constants.js` | `DEFAULT_BACKEND`、`BACKEND_SUGGESTIONS` |
| `src/views/Subconverter.vue` | `:placeholder="backendPlaceholder"`（随构建环境变化） |
| `index.html` | favicon 相对路径 `favicons/...` |
| `nginx.subw.conf` | 子路径重写、根路径跳转、NPM 剥前缀兼容 |
| `Dockerfile` | 覆盖默认 Nginx 配置 |
| `.env.default` | master 同款默认部署（【必改】0 项） |
| `.env.example` | NPM 子路径脱敏模板（【必改】2 项） |
| `.gitignore` | 忽略 `.env` |

### 3.1 容器内 Nginx（`nginx.subw.conf`）

| 路径 | 行为 |
|------|------|
| `/` | 无 `X-Forwarded-Prefix` → `302 /subw/`（直连映射端口） |
| `/` | 有 `X-Forwarded-Prefix: /subw`（NPM 剥前缀）→ 返回 `index.html` |
| `/subw/` | 重写为磁盘路径 `/assets/...` 等 |
| `/subw` | `302 /subw/` |

NPM 需在 `location ^~ /subw/` 中设置：`proxy_set_header X-Forwarded-Prefix /subw;`

### 3.2 后端下拉（构建后）

1. `VITE_SUBCONVERTER_DEFAULT_BACKEND` + `/sub?`（生产默认）
2. `VITE_BACKEND_OPTION_LOCAL`（可选，本地调试）

## 4. 构建与发布

```bash
# Node 22.x（见 package.json engines）
cp .env.production.example .env   # 编辑为真实域名与端口
yarn install
yarn build
docker build --platform linux/amd64 -t subweb:nas-amd64 .
```

QNAP 示例（宿主机端口按预检选取，避免冲突）：

```bash
docker run -d --name subweb -p <HOST_PORT>:80 --restart always subweb:nas-amd64
```

经 NPM `location ^~ /subw/` 反代时，**可不**对公网暴露该宿主机端口。
